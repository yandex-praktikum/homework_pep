# Асинхронный парсер PEP

Создайте Scrapy-парсер [документов PEP](https://peps.python.org/). Он сохраняет список PEP и сводку по статусам в двух
CSV. БД, авторизация, requests-html и Selenium в этот проект не входят.

## Подготовка

Нужен Python 3.14. Создайте виртуальное окружение: `python -m venv venv` (на Linux/macOS используйте `python3.14`).
Активируйте его: Windows — `venv\Scripts\Activate.ps1`, Linux/macOS — `source venv/bin/activate`. Если в Windows команда
`python` запускает другую версию, используйте установленный Python 3.14; проверьте `python --version` после активации.

Из корня репозитория установите зависимости: `python -m pip install -r requirements.txt`, затем выполните
`python -m pip check`.

В каркасе проект ещё не создан: выполните `python -m scrapy startproject pep_parse .`, затем
`python -m scrapy genspider pep peps.python.org`. В готовом решении повторять эти команды не нужно.

## Что реализовать

1. Проект называется `pep_parse`, паук — `pep`. Файл `scrapy.cfg` находится в корне репозитория `scrapy_parser_pep`,
   рядом с `pep_parse/` и `tests/`. Запуск: `python -m scrapy crawl pep` из корня.
2. Стартовый адрес — `https://peps.python.org/`. В `parse()` соберите ссылки на PEP. На текущем сайте числовой индекс
   доступен по ссылке в разделе Numerical Index; перейдите по ней и разберите таблицу. Один PEP может быть представлен
   несколькими ссылками. На выходе должна остаться одна запись на номер PEP.
3. В `parse_pep()` извлеките номер, название и полный статус документа CSS- или XPath-селекторами. На текущих страницах
   номер входит в заголовок `PEP 20 – The Zen of Python`, а значение статуса вложено в `<abbr>` внутри `<dd>`. Сохраните
   название целиком из заголовка, включая префикс PEP. Уберите пробелы по краям значений; все три поля должны быть
   заполнены.
4. Опишите `PepParseItem(scrapy.Item)` с полями `number`, `name`, `status`. Передавайте Item из обработчика дальше по
   цепочке Scrapy.
5. В `settings.py` настройте Feeds для списка документов и подключите Pipeline. Pipeline накапливает количества по
   статусам и сохраняет сводку после завершения обхода.

## Результаты

Папка `results/` создаётся автоматически в корне, рядом с `pep_parse/` и `tests/`. Оба файла — CSV в UTF-8 с
разделителем-запятой.

| Файл | Заголовок | Строки |
| --- | --- | --- |
| `pep_ДатаВремя.csv` | `Номер,Название,Статус` | Один документ — одна строка. |
| `status_summary_ДатаВремя.csv` | `Статус,Количество` | Строка на статус; в конце — `Total` и общее число документов. |

Используйте одинаковую временную метку в именах пары: `YYYY-MM-DDTHH-MM-SS`, например `pep_2026-10-17T12-30-00.csv` и
`status_summary_2026-10-17T12-30-00.csv`. Стандартная подстановка Scrapy `%(time)s` содержит также часовой пояс; для
требуемого формата можно передать свою метку через атрибут паука и подстановку `%(run_time)s`. Конкретное имя такого
атрибута не обязательно.

Новый запуск создаёт новую пару; старые файлы не перезаписываются и новые строки к ним не дописываются. Порядок
документов и статусов свободный; `Total` всегда последний. Число документов и набор статусов на сайте не фиксированы. Для
корректной записи запятых и переводов строк используйте CSV-инструменты; при ручной записи сводки через `csv` открывайте
файл с `newline=''`.

При ошибке загрузки или отсутствии обязательного поля сообщите о проблеме в логе. Не выдавайте неполный обход за полный:
итоговую сводку для такого запуска не создавайте. Частичный список можно оставить для диагностики. После устранения
ошибки выполните новый запуск.

## Проверка

`python -m pytest -q` проверяет селекторы и выгрузку на локальных HTML-примерах. Тесты сами поднимают временный локальный
HTTP-сервер, живой сайт для них не нужен. В пустом каркасе проверки не проходят: сначала создайте проект и выполните
задание.

Отдельно запустите `python -m scrapy crawl pep` по настоящему сайту. Проверьте лог, откройте оба CSV и сравните сводку с
подсчётом по списку. Код возврата команды Scrapy сам по себе не доказывает, что обход был полным.

Перед сдачей проверьте:

- проект устанавливается на Python 3.14;
- список сохраняется через Feeds, сводка — через Pipeline;
- заголовки, кодировка, пути и имена соответствуют заданию;
- номера не дублируются, поля заполнены, количества и Total совпадают со списком;
- повторный запуск сохраняет предыдущие файлы;
- локальные тесты проходят, полный запуск по сайту проверен отдельно;
- README коротко сообщает, как установить и запустить проект и где искать результат.

Имена внутренних констант, конкретный CSS-селектор, имя класса Pipeline, порядок ответов и точный текст сообщений не
являются дополнительными требованиями.
